# UFO-0.1 — setup, sumber, fitur, dan semua perubahan

Disusun dari berkas di repo ini (`build-kit/ci/ufo01/`, `.github/workflows/ufo-01-build.yml`,
`docs/`), bukan dari ingatan. Setiap angka di sini bisa diperiksa ulang dengan perintah
yang ditulis di akhir.

## 1. Sumber yang dipakai

| Bahan | Asal | Penanda |
|---|---|---|
| Pohon kernel | `clarencelol/kernel_xiaomi_sm6250` | branch `kinesis-v29`, commit `427fbc7`, Linux **4.14.344** (openela) |
| Perangkat | Xiaomi **miatoll** / sm6250 (Redmi Note 9 Pro family) | `arch/arm64/configs/vendor/xiaomi/miatoll_defconfig` |
| KernelSU | **KernelSU-Next**, fork `sidex15/KernelSU-Next` | branch `legacy-susfs-v2` @ `d999a2aff115` (22 Sep 2026), version_code 30000 |
| SuSFS | **v2.3.0**, varian **NON-GKI** | port 4.14 dari `JackA1ltman/NonGKI_Kernel_Build_2nd` |
| NoMount | **v2.0.0** (`maxsteeel/nomount`) | tag object `b8d2683…`, disalin apa adanya, di-build-in karena 4.14 tak bisa muat LKM rilis |
| AnyKernel3 | osm0sis | dipakai apa adanya untuk paket zip |
| Toolchain | Debian `clang-18` / `lld-18` / LLVM 18 | `LLVM_IAS=1`, `ld.lld`, `llvm-ar/nm/objcopy/objdump/strip` |

**Kenapa fork `legacy-susfs-v2`, bukan KernelSU-Next upstream:** upstream tidak punya
dukungan SuSFS dan tidak punya kerja manual-hook untuk 4.14. Fork ini menyediakan
`CONFIG_KSU_SUSFS_*`, API `CONFIG_KSU_MANUAL_HOOK` untuk 4.14, dan bisa dibangun tanpa
kprobes.

**Kenapa SuSFS dari port komunitas, bukan simonpunk:** `simonpunk/susfs4ksu` resmi
berhenti di v1.5.1; dukungan legacy 4.14 untuk v2.3.0 datang dari port komunitas itu.

**Konsekuensi userspace yang wajib dipenuhi:**
- Modul `susfs4ksu` harus **v2.x** (`ksu_susfs`). Skrip `susfs4ksu.sh` v1.5.x **tidak
  kompatibel** — `add_open_redirect()` dapat argumen ketiga `<UID_SCHEME>`.
- NoMount butuh **metamodul** (`nm` CLI lewat kernel keyring, `add_key(2)`; bukan ioctl,
  bukan device node).
- Manager harus cocok dengan KernelSU-Next fork ini (root sebagai metamodul).

## 2. Fitur yang aktif — dan buktinya

Kolom "bukti" adalah yang membedakan dokumen ini dari daftar keinginan. `PROOF.txt`
membaca instruksi mesin (BL/ADRP/POINTER), bukan string.

| Fitur | Config | Bukti dari build `facd6c6` |
|---|---|---|
| **MGLRU** | `LRU_GEN=y`, `LRU_GEN_ENABLED=y`, `NR_LRU_GENS=7`, `LRU_GEN_STATS` mati | `shrink_page_list` → `BL` → `lru_gen_eviction` |
| **UCLAMP** | `UCLAMP_TASK=y`, `UCLAMP_TASK_GROUP=y`, `UCLAMP_BUCKETS_COUNT=5` | `__schedule` → `BL` → `uclamp_rq_inc_id`; `sched_init` memuat `uclamp_default` |
| **WALT** | `SCHED_WALT=y`, `SCHED_TUNE=y` | `__schedule` **dan** `try_to_wake_up` → `BL` → `update_task_ravg` |
| **KernelSU** | `KSU=y`, `KSU_MANUAL_HOOK=y` | `do_execveat_common` → `BL` → `ksu_handle_execveat` |
| **SuSFS** | `KSU_SUSFS=y` + 9 opsi (lihat bawah) | `link_path_walk` → `BL` → `susfs_is_inode_sus_path` |
| **NoMount** | `NOMOUNT=y` | `nm_dir_iops` menunjuk `nm_dir_lookup`; `nm_dir_fops` menunjuk `nm_dir_iterate_dir` |

Identitas yang dipanggang ke Image: **`4.14.344-openela-UFO-0.1`**
(`CONFIG_LOCALVERSION="-UFO-0.1"`).

### Opsi SuSFS: 9 nyala, 2 mati

Nyala: `SUS_PATH`, `SUS_MOUNT`, `SUS_KSTAT`, `SPOOF_UNAME`, `ENABLE_LOG`,
`HIDE_KSU_SUSFS_SYMBOLS`, `SPOOF_CMDLINE_OR_BOOTCONFIG`, `OPEN_REDIRECT`, `SUS_MAP`.

Mati: `TRY_UMOUNT`, `SUS_MEMFD`.

**`TRY_UMOUNT` mati bukan kelalaian — itu wajib.** Port SuSFS v2.3.0 untuk 4.14 ini
tidak menyediakan `susfs_try_umount()`/`susfs_add_try_umount()`, sementara
KernelSU-Next masih memanggil keduanya di `supercall/supercall.c:158` dan
`hook/setuid_hook.c` di bawah `#ifdef CONFIG_KSU_SUSFS_TRY_UMOUNT`. Kalau dinyalakan,
**build gagal** (implicit declaration, lalu undefined reference). Yang dipakai sebagai
gantinya: jalur `ksu_handle_umount()` milik fork itu sendiri. Audit menolak build bila
opsi ini dinyalakan.

> Koreksi: sebelumnya saya menyarankan menyalakan `TRY_UMOUNT`. Saran itu salah dan
> sudah saya batalkan setelah memeriksa `check_susfs_symbols.py` dan `CARA-PASANG`.

`SUS_MEMFD` mati karena memang tidak pernah diminta. Menyalakannya butuh pemeriksaan
simbol yang sama dulu, belum dicoba.

## 3. Perubahan pada pohon kernel

### a. Patch besar: `01-synthetica32-and-susfs-tracking.patch`
268 KB, menyentuh **67 berkas**, **+5.562 / −296** baris. Isinya:

- **MGLRU 4.14** — `mm/` (vmscan, workingset, swap, swapfile, swap_state, rmap,
  memcontrol, huge_memory, memory, pagewalk, mmzone, mm_init, mmu_context, Kconfig,
  `include/linux/page-flags.h`, `include/linux/swap.h`)
- **UCLAMP + WALT + SCHED_TUNE** — `kernel/sched/` (core, fair, rt, sched.h,
  cpufreq_schedutil), `include/linux/sched.h`, `include/uapi/linux/sched*.h`,
  `kernel/sysctl.c`, `include/linux/sched/sysctl.h`
- **Hook SuSFS** — `fs/` (namei, namespace, stat, statfs, readdir, super, proc/*,
  notify/fdinfo, proc_namespace), `kernel/` (kallsyms, sys, sysctl), `mm/memory.c`,
  `security/selinux/` (avc, hooks)
- **Wiring** — Kconfig/Makefile di `fs/`, `drivers/`, `init/`, `mm/`, `kernel/`
- **Defconfig** — `arch/arm64/configs/vendor/xiaomi/miatoll_defconfig`

### b. Berkas baru yang disalin masuk
- `KernelSU-Next/` (724 KB) → di-*symlink* sebagai `drivers/kernelsu`
- `fs/nomount/` (NoMount v2.0.0)
- `fs/susfs.c` (60 KB), `include/linux/susfs.h`, `susfs_def.h`
- `tools/root-integration/` (audit, hook applier, symbol checker, patch SuSFS)

### c. KernelSU bawaan Kinesis di-unhook, bukan dihapus
Kinesis mengirim KernelSU biasa di `drivers/staging/kernelsu`. Dengan KernelSU-Next
hadir, keduanya terkompilasi dan **linker berhenti pada 20 simbol duplikat**
(`ksu_type`, `is_manager_apk`, `track_throne`, …). Dua baris di
`drivers/staging/{Makefile,Kconfig}` dikomentari. Sumbernya **tidak dihapus** — dan
build gagal kalau hooking ini tidak berhasil.

### d. Tiga perbaikan yang diminta log build (`fixups/apply-tree-fixups.sh`)
1. **Wiring KSU tepat satu baris.** `mrproper` me-reset `drivers/Makefile`, sehingga
   `CONFIG_KSU` hilang diam-diam dan muncul "No hooks were defined". Dua baris wiring
   membuat modul terkompilasi dua kali dan simbolnya duplikat lagi.
2. **Dua simbol sysctl yang tidak pernah didefinisikan.** Kinesis mendaftarkan
   `sched_conservative_pl` dan `sched_many_wakeup_threshold` di `kernel/sysctl.c` tapi
   tidak ada yang mendefinisikannya → `vmlinux` gagal link. Definisi ditambahkan di
   `kernel/sched/tune.c`.
3. **`path_umount` di Kbuild KernelSU-Next** diinjek lewat `sed` yang jangkarnya tidak
   cocok di pohon ini.

### e. Di luar berkas kernel
- `.github/workflows/ufo-01-build.yml` — build, audit, bukti, gerbang, publikasi
- `verify_image.py`, `prove_features.py`, `root_stack_report.py`, `show_version.py`
  — alat bukti (lihat bagian 6)
- `anykernel/anykernel.sh` — paket flash: **tidak** mengganti DTB, **tidak** menimpa
  `/data/adb/ksud`, cmdline dipertahankan kecuali sisa eksperimen lama

## 4. Arti "8 patch Synthetica" — dan koreksinya

Ada dua hal berbeda yang keduanya sering disebut "8 patch":

**Yang berhasil menempel di pohon Synthetica (`4.14.357`), 13 Nov:**
```
BERSIH   0001-mglru-4.14.patch
BERSIH   0002-uclamp-walt-stune.patch
KONFLIK  0003-uclamp-correctness.patch      (dua kali)
BERSIH   0004-mglru-anon-file.patch
KONFLIK  0005-mglru-pagewalk-caf.patch       (dua kali)
BERSIH   0006-neutron-enum-cast.patch
BERSIH   0001-ksu-manager-preserve-seccomp.patch
BERSIH   0001-manager-fd-after-exec.patch
```
6 bersih, 2 konflik — konfliknya sudah diselesaikan di repo ini, dan hasil akhirnya
dibekukan menjadi **satu berkas**: `01-synthetica32-and-susfs-tracking.patch`.

**Yang menempel di UFO-0.1 (Kinesis 4.14.344):** **satu** patch itu. Klaim "semua 8
patch menempel tanpa `.rej`" di `CARA-PASANG` berlaku untuk pohon Synthetica 4.14.357,
**bukan** untuk UFO-0.1. Untuk UFO-0.1, yang benar: satu patch gabungan menyentuh 67
berkas dan menempel bersih.

Perbedaan pohon juga nyata: Synthetica `4.14.357`, UFO-0.1 `4.14.344`.

## 5. Alur build (13 langkah, run `43676566211` hijau)

1. **Toolchain** — clang-18, lld-18, LLVM 18, cross `aarch64-linux-gnu-` + `arm-linux-gnueabi-`
2. **Clone Kinesis** `kinesis-v29` (depth 1)
3. **Tanam stack**: salin KernelSU-Next, nomount, susfs; unhook KSU bawaan; symlink
   `drivers/kernelsu`; apply patch; salin defconfig
4. **Audit** — `audit_hooks.sh`, harus cetak `AUDIT PASSED (0 errors`. Yang dicek:
   pohon vendored, versi SuSFS/NoMount, wiring Kbuild/Kconfig, **26 titik hook SuSFS**,
   `fs/stat.c` menyertakan `susfs_def.h`, resolusi simbol, call site manual hook,
   dan defconfig
5. **Build** — `mrproper` (kode keluarnya diperiksa), symlink ulang, fixups, `olddefconfig`,
   lalu `make O=out ARCH=arm64 Image.gz` dengan `CC=clang`, `LD=ld.lld`, `LLVM_IAS=1`
6. **Error pertama** — dicetak, karena endpoint log 404 dari luar
7. **Rakit zip** — AnyKernel3
8. **Kumpulkan bukti** — `System.map`, `config.final`, `PROOF.txt`
9. **Terbitkan log** — branch `ufo-evidence`
10. **Laporan** — apa yang dibuat dan apa yang **tidak** diuji
11. **Gerbang** — `prove_features.py`; exit 1 (tidak ada/tidak tersambung) dan exit 2
    (tidak bisa dijawab) **sama-sama menggagalkan build**
12. **Terbitkan zip** — branch `ufo-release`
13. **Simpan Image** — artifact 14 hari

## 6. Alat bukti — kenapa tiga lapis

Setiap alat ada karena versi sebelumnya memberi jawaban salah.

| Alat | Menjawab | Catatan |
|---|---|---|
| `verify_image.py` | penanda **KUAT** di Image: `uclamp.min/max`, `walt_stats.nr_big_tasks`, `ksu_driver` | **bukan gerbang**. Tidak bisa menjawab MGLRU/SuSFS/NoMount, dan mengatakannya |
| `root_stack_report.py` | simbol per fitur + titik masuk yang diharapkan | pembanding; daftar simbolnya pernah salah (nama dari kernel 6.x) |
| `prove_features.py` | **gerbang**. Mendekode `BL`/`ADRP`/`ADD` dan menanyakan apakah fungsi kernel memanggil fitur | punya self-test untuk ketiga dekoder; self-test itu menemukan dua bug di alat ini sendiri |

Yang **tidak** sah sebagai bukti, dan sudah dicoba: string di `Image.gz`, string di
Image yang dibuka, `CONFIG_X=y`, dan daftar nama simbol dari ingatan.

## 7. Yang belum terbukti — jangan dianggap selesai

1. **Boot.** Tidak ada satu pun catatan kernel ini menyala.
2. **Performa, drain, panas, deep sleep.** Nol angka. Klaim "tanpa drain / tanpa panas"
   belum punya dasar apa pun.
3. **SuSFS baru terbukti di satu titik** (`susfs_is_inode_sus_path` dari
   `link_path_walk`). Delapan opsi lain punya config dan simbol, belum punya rantai bukti.
4. **`SUS_MEMFD`** belum dicoba.
5. **DTB** tidak diganti paket ini; DTB dari ROM dipertahankan.
