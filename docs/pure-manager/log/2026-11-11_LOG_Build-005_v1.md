## 2. Penyebab

Haze menetapkan aturan: node `Modifier.haze` (sumber) **tidak boleh** menjadi
leluhur node `Modifier.hazeChild` (bar), dan sebaliknya. Alasannya masuk akal —
sumber merender isinya ke graphics layer, lalu bar memblur layer itu. Kalau bar
ada *di dalam* sumber, ia akan memblur dirinya sendiri.

Kode 0.1.2/0.1.3:

```kotlin
Box(Modifier.fillMaxSize().glassSource(spec, haze)) {   // <- sumber
    Column(Modifier.verticalScroll(scroll)) { ... }
    TopBar(...)      // <- DI DALAM, dan TopBar berisi GlassBar = hazeChild
}
```

Bar menjadi turunan dari sumbernya. Haze melempar dari dalam proses menggambar
(`HazeChildNode.draw`), jadi yang terjadi bukan tampilan jelek — **proses mati
pada frame pertama**.

Karena perangkatnya API 36, jalur blur aktif di setiap pembukaan. Itu sebabnya
selalu force close, bukan kadang-kadang.

### Perbaikan

```kotlin
Box(Modifier.fillMaxSize()) {                          // Box biasa
    Column(Modifier.fillMaxSize().glassSource(spec, haze)) { ... }  // sumber
    TopBar(...)                                        // saudara, bukan anak
}
```

Satu `HazeState` per layar tetap dipakai bersama. Sumber dan bar sekarang
bersaudara.

---

## 3. Penjaga: dua percobaan, dan yang pertama gagal

Saya tulis tes yang berjalan di atas sumber Kotlin. **Versi pertamanya lolos di
kode yang rusak** — karena ia mencari `GlassBar(` yang bersarang, sedangkan
`TopBar` hanya *memanggil* `GlassBar`. Tes yang hijau di bug yang sebenarnya
lebih buruk daripada tidak ada tes.

Versi kedua melacak lebih dulu composable mana yang **membawa** bar (langsung,
lalu satu tingkat pemanggilan), baru memeriksa sarang. Dibuktikan dengan
mengembalikan struktur 0.1.2:

```
FAIL: test_source_and_bars_are_siblings
AssertionError: TopBar() at line 319 is nested inside the glassSource block
opened at line 278; Haze throws 'can not be descendants of each other'
```

Baru setelah itu dipercaya.

## 4. Masalah kedua yang ikut diperbaiki

Safe mode saya bertanya *"pernah crash?"* — bukan *"crash di versi ini?"*.

Akibatnya: laporan 0.1.3 yang tersimpan akan membuat **setiap** pembukaan 0.1.4
masuk safe mode dengan **blur mati**. Perbaikan yang berhasil akan terlihat
seperti efek kaca yang rusak, dan saya akan mengejar bug yang tidak ada.

Sekarang `crashedOnThisVersion()` membandingkan `appVersion` di laporan dengan
versi yang berjalan. Laporan lama tetap terbaca di Setelan, tapi tidak lagi
mengubah cara aplikasi start.
