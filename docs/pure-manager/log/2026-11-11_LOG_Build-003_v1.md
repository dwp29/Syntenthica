## 2. Soal "glass / blur" — yang menentukan

Ini bagian yang saya paling tidak mau palsukan. Kotak abu semi-transparan **bukan**
kaca. Di iOS, efeknya terasa justru karena isi di belakangnya ikut kabur saat
digulir.

Saya pakai **Haze** — library yang merender isi ke graphics layer lalu memblur
dengan `RenderEffect` (Android 12+). Di bawah Android 12, Haze jatuh ke scrim
transparan; itu batas jujur platform, dan sebabnya tint sama pentingnya dengan
radius.

**Versi dipilih dengan hati-hati:**

| Haze | Kotlin | AGP |
|---|---|---|
| 2.1.0 | 2.4.21 | 9.5.0 |
| 1.6.10 / 1.4.0 / 1.2.2 | **2.1.0** | 8.8–8.12 |
| **1.1.1** | **2.0.21** | **8.7.3** |

Proyek ini Kotlin 2.0.21 / AGP 8.7.3. **Haze 1.1.1 persis cocok** — tidak perlu
menaikkan toolchain hanya demi blur, yang berarti pula tidak ada risiko merusak
build yang baru saja stabil. Diverifikasi: kelas `chrisbanes/haze` benar-benar
masuk ke dalam APK.

**Blur adalah token, bukan kondisi tema:**

```kotlin
enum class ChromeStyle { SOLID, GLASS }
```

Hanya iOS yang `GLASS`. Windows dan Cyberpunk tetap solid — lebih tajam, lebih
hemat baterai, dan `Glass.kt` tidak menyebut satu pun id tema.

## 4. Enam tes baru (total 27)

1. Blur benar-benar ada — dependensi Haze wajib, `hazeChild` + `blurRadius` dipakai
2. **Batas atas versi Haze** — kalau ada yang menaikkan ke 1.2+, tes gagal karena
   butuh Kotlin 2.1
3. Glass adalah token, bukan cek id tema
4. **Hanya iOS** yang boleh menyalakan glass
5. Ciri khas iOS ada: `useLargeTitle`, `defaultGrid`, `floatingAction`, `separator`
6. Tidak ada `fontSize = ` yang ditulis mati

Tes nomor 2 penting: kalau nanti Haze dinaikkan tanpa sengaja, yang gagal adalah
tes ini, bukan build tiga menit kemudian.

Satu tes sempat gagal ditulis karena escaping di heredoc; diperbaiki di tesnya,
bukan di kodenya.
