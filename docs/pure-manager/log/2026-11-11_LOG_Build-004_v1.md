## 1. Yang dilaporkan

> Force close tidak bisa di buka

0.1.2 mati saat dibuka. Tidak ada logcat, tidak ada stack trace, dan sandbox ini
tidak bisa mengunduh log CI maupun artifact. **Saya tidak akan menebak-nebak
penyebab matinya aplikasi yang tidak bisa dibuka sama sekali** — itu cara
menghabiskan tiga putaran lagi.

## 2. Dua tersangka, dari kode Haze sendiri

Saya baca sumber Haze 1.1.1 baris per baris. Ketemu dua jalur yang **bisa
mematikan proses**, dan keduanya bergantung perangkat:

### Tersangka 1 — RenderEffect menolak radius blur

```kotlin
// RenderEffect.android.kt:64
throw IllegalArgumentException(
  "Error whilst calling RenderEffect.createBlurEffect. " +
    "This is likely because this device does not support a blur radius of ...dp",
  e,
)
```

Sebagian perangkat menolak `RenderEffect.createBlurEffect`. Haze melempar ulang
sebagai error — **dari dalam proses menggambar**. Itu mematikan aplikasi, bukan
cuma memperlihatkan bar tanpa blur.

### Tersangka 2 — warna latar tidak ditentukan

```kotlin
// HazeChildNode.kt:327
require(bg.isSpecified) { "backgroundColor not specified. Please provide a color." }
```

`HazeStyle` bawaan punya `backgroundColor = Color.Unspecified`. Saya mengandalkan
`glassTint` dan tidak pernah menetapkan `backgroundColor` — bergantung jalur mana
yang dipakai, `require` ini bisa terpicu.

**Keduanya tidak bisa saya pastikan mana yang terjadi. Karena itu perbaikannya
bukan menebak: saya buat supaya keduanya tidak lagi bisa mematikan aplikasi.**

## 3. Yang diperbaiki

### Blur tidak lagi bisa mematikan aplikasi

- **Gerbang SDK 31+** di titik pakai. Di Android 10–11 Haze memang mengembalikan
  `null`, tapi sekarang keputusannya diambil sebelum masuk ke jalurnya.
- **Bisa dimatikan** dari Setelan → Efek kaca. Tidak ada tema yang jadi jalan
  buntu: kalau blur bermasalah, ada jalan pulang tanpa memasang ulang.
- **Jatuh ke tint, bukan ke kosong.** Kalau blur tidak tersedia, bar memakai
  warna `glassTint` — persis yang Haze sendiri lakukan di bawah API 31.
- Preferensi `blur` **ikut disimpan** di saver; kalau tidak, tombolnya akan
  diam-diam kembali menyala setiap rotasi.

### Safe mode

Kalau run sebelumnya meninggalkan laporan crash, run berikutnya **mulai dengan
blur mati dan tampilan awal**, cukup untuk sampai ke tab Setelan dan membaca
laporannya. Muncul banner yang bisa ditutup di layar Berkas.

### Pelapor crash — lokal, tidak dikirim ke mana pun

Memasang `UncaughtExceptionHandler` **sebagai delegasi**, bukan penangkap:
handler bawaan tetap dijalankan sesudahnya, jadi dialog sistem dan tombstone
berperilaku normal. Yang dicatat: exception, message, **cause**, stack 40 frame,
thread, versi Android, perangkat, versi aplikasi.

Ditampilkan di **Setelan → Laporan crash**, dengan tombol **Salin**. Tidak ada
jaringan sama sekali.

## 4. Dua build gagal, dan apa yang diajarkan

### Build #10

```
e: MainActivity.kt:41:17 Try catch is not supported around composable
   function invocations.
```

Rencana awal saya membungkus komposisi dengan `try/catch`. **Compose melarangnya** —
jadi kegagalan di dalam komposisi tidak bisa ditangkap di tempat kejadiannya.
Bentuk perbaikannya salah, bukan cuma kodenya. Diganti dengan safe mode yang
dipulihkan saat start.

### Build #11

```
e: PureShell.kt:289:21 Unresolved reference 'recoveredFromCrash'.
```

Kesalahan yang **sama bentuknya** dengan bug yang Anda temukan kemarin: sebuah
nama dipakai di dalam fungsi yang tidak pernah menerimanya. Banner saya sisipkan
satu lapis terlalu dalam.

Kali ini saya tidak berhenti di memperbaiki nama itu. Saya tulis penjaga yang
**menelusuri setiap composable**, mencari parameter yang dipakai di badan fungsi
tapi tidak ada di tanda tangannya. Dibuktikan dengan menghapus parameternya lagi
dan melihat tes gagal dengan pesan yang sama.
