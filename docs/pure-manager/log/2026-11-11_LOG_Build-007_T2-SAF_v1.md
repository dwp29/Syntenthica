## 1. Kenapa irisan kecil ini dikerjakan

Di log build 006 saya menulis sendiri bahwa tombol **"Pilih satu folder saja"**
belum tersambung — hanya memunculkan pesan "menyusul". Saya mencatatnya sebagai
kekurangan, bukan menyembunyikannya.

Masalahnya: tombol itu **menjanjikan fitur lalu tidak melakukan apa pun**. Itu
lebih buruk daripada tombol yang tidak ada. Jadi ditutup sebelum jadi kebiasaan.

## 2. Yang sekarang tersambung

| Bagian | Perilaku |
|---|---|
| `OpenDocumentTree` | membuka pemilih folder Android |
| `takePersistableUriPermission` | diperiksa **sebelum** izin disimpan |
| Daftar folder pilihan | bertahan setelah aplikasi ditutup |
| Membaca isi folder SAF | lewat content resolver, bukan `java.io.File` |
| Tombol **⊕** | menambah folder lain kapan saja |

Kalau izin permanennya ditolak, muncul pesan — bukan folder yang terdaftar lalu
gagal dibuka di peluncuran berikutnya. Folder yang gagal dibuka terbaca sebagai
**kehilangan data**, dan itu kesan yang mahal.

## 3. Satu tes yang salah dulu

Saya menulis: *"'menyusul' tidak boleh muncul di mana pun"*.

Tes itu **gagal** — dan benar gagal, karena kata yang sama juga dipakai di pesan
jujur saat menekan berkas: *"Pembuka berkas menyusul (tahap 5)"*. Itu bukan janji
palsu; membuka berkas memang belum ada.

Tes dipersempit ke dua handler yang benar-benar dijanjikan:

```python
assertRegex(browser, r"onPickFolder = \{ folderPicker\.launch")
assertRegex(browser, r"onAddFolder = \{ folderPicker\.launch")
```

## 4. Dua jalur, keduanya nyata

1. **Semua Berkas** — Setelan Android, akses `File` penuh, bisa mengubah
2. **Pilih folder (SAF)** — tanpa izin khusus, tersimpan permanen

Kalau MIUI menampilkan halaman Setelan kosong (kejadian umum di Redmi), jalur
kedua tetap bekerja. Itu sebabnya keduanya dipasang.
