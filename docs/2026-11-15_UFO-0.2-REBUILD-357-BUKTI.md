## Satu bug yang hampir membatalkan semuanya

`check_block()` di `drivers/kernelsu/manager/apk_sign.c`:

```c
#define CERT_MAX_LENGTH 1024
if (certificate_size != expected_size) return false;
if (certificate_size > CERT_MAX_LENGTH) { ...; return false; }
```

Saat itu kernel dipatok ke sertifikat Pure Manager, yang berukuran **1373 byte**,
dan `EXPECTED_MANAGER_SIZE` juga 1373. Jadi syarat kedua adalah `1373 > 1024` —
selalu benar. Kompiler membuang perbandingannya.
Disassembly `check_block` pada image lama membuktikannya:

```
LDR   w8, [x31]
SUBS  x8, #1373
B.NE  fail
      <- tidak ada perbandingan batas sama sekali
BL    printk          <- jatuh lurus ke "cert length overlimit"
```

Artinya kernel menolak manager-nya sendiri, dan satu-satunya jejak adalah satu baris
di dmesg. Mengisi `KSU_NEXT_MANAGER_SIZE/HASH` perlu, tapi **tidak cukup**.

Sekarang `CERT_MAX_LENGTH` = 4096, dan ada gerbang `verify_manager_bound.py` yang
membaca `check_block` dari image hasil build. Tidak ada banding di atas 1373 = build
gagal. Terbukti dua arah: image batas 1024 → GAGAL exit 1; image batas 4096 → LULUS exit 0.

## Perbaikan pohon yang ikut ditanam

Semua oleh `build-kit/ci/ufo02/apply_synthetica357.sh`, idempoten, diuji di pohon bersih:

1. **Enam patch Synthetica** berurutan 0001→0006. Wajib berurutan: 0003 mengubah
   tipe pada kode yang dibuat 0002, 0005 menyentuh halaman yang ditulis 0001.
2. **`aw8624.h`**: `linux/timed_output.h` tidak ada di 4.14; header ada di
   `drivers/staging/android/`. Dipakai path relatif — sama seperti `drv2624.h`.
   Config tidak dimatikan, karena itu akan menghapus haptic perangkat.
3. **`path_umount`** disuntik ke `fs/namespace.c` sebelum build. Kbuild KernelSU-Next
   melakukannya sendiri lewat `sed`, tapi hanya menang bila `drivers/` dibaca sebelum
   `fs/`. Dengan `make -j` itu balapan — build sebelumnya kalah dan gagal link.
4. **`CERT_MAX_LENGTH` 1024 → 4096**, seperti di atas.

## Yang BELUM terbukti

- **Belum di-flash.** Tidak ada bukti boot. Zip ini belum pernah dijalankan di perangkat.
- **Belum ada angka**: baterai, drain saat idle, deep sleep, suhu, performa.
- **Deep sleep** bukan fitur yang ditanam patch. Ia bergantung pada wakelock, modem, dan
  ROM. Yang bisa dikatakan hanya: basis 357 dan SuSFS/KSU tidak menambah wakelock —
  itu pun belum diukur.
- **Manager di perangkat**: kernel akan mengenali sertifikat APK, tapi apakah KSU
  berjalan normal di ROM Anda belum diuji.

## Cara memasang

1. Rekam `boot.img` asli dulu.
2. Recovery (TWRP/OrangeFox) → Install → pilih zip.
3. Reboot. Kalau gagal boot, kembalikan `boot.img` tadi.

Jangan ganti APK manager dengan build lain tanpa mengganti hash di `build_ufo02.sh`,
lalu jalankan `verify_manager.sh` untuk memastikannya cocok.

## Koreksi: pin manager dicabut

Dokumen ini awalnya menyebut kernel dipatok ke sertifikat Pure Manager 0.10.0.
Itu **keliru dan sudah dibatalkan**. Pure Manager adalah aplikasi penjelajah berkas,
bukan manager KernelSU; memasang sertifikatnya di kernel tidak memberinya kemampuan
mengelola izin root.

Kernel sekarang dibangun tanpa `KSU_NEXT_MANAGER_SIZE`/`KSU_NEXT_MANAGER_HASH`,
sehingga memakai sertifikat manager bawaan pohon — yaitu manager KernelSU-Next
resmi. Lihat `PURE-MANAGER-DISCONTINUED.md`.

Perbaikan `CERT_MAX_LENGTH` tetap dipertahankan: itu bug nyata yang membuat kernel
menolak sertifikat mana pun yang lebih besar dari 1024 byte, terlepas dari APK yang
dipakai.
